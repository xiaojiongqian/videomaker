# Story Engine

把“更精彩”拆成少数可复用的内部检查，而不是更多空泛要求。

## Chapter Promise

在规划或扩写前，先在内部确认这一章的最小引擎：

1. `disturbance`
   - 什么在本章一开始就打破了原有平衡
2. `pursuit`
   - 这一章里，谁最急着想拿到什么
3. `escalation`
   - 什么让事情越来越难
4. `irreversible turn`
   - 哪个节点一旦发生，就不能再当没发生
5. `residue`
   - 章末留下了什么压力、债务、风险或未完成感

如果这五项里缺了两项以上，章节通常会滑向总结、综述或履历稿。

## Core Event

每章默认至少应有一个不可删除的核心事件。

- 如果删掉这个事件，章节推进应明显受损
- 如果一章里所有段落都像可有可无的说明或桥接，说明核心事件还没有真正落地
- 对纪实骨架章节，这个核心事件常常就是：
  - 一个比分被改写的瞬间
  - 一次名单 / 身份 /号码变化
  - 一次失利把提问改写
  - 一段走廊、点球点、领奖台前的强余波

## Character Engine

关键人物不要只有“身份”和“功能”，至少要有最小可写引擎：

- `want`
  - 此刻想保住、拿到或阻止什么
- `risk`
  - 如果失败，会失去什么
- `pressure tell`
  - 压力落下时，动作、语言、节奏或回避方式如何变化
- `contradiction`
  - 这个人一边想要什么，一边又被什么拖住

对于纪实、历史、现实向写法：

- 如果来源不支持私密动机，不要硬写内心
- 把 `want / fear` 翻译成公开可见的等价物：
  - 即时目标
  - 外部代价
  - 位置矛盾
  - 可观察压力反应

## Scene Card

每个硬场面尽量能压成一张 scene card：

1. 进入时已有压力
2. 有人追求即时目标
3. 有阻力或反作用力
4. 有一次主动动作
5. 局面发生偏转
6. 留下代价、痕迹或未竟后果

如果一段只有“情况如何”而没有“谁做了什么把情况改变”，那通常还不是场面。

## Scene Cell

对关键段落，优先再过一遍更轻量的 `scene cell` 检查：

1. `anchor`
   - 可见时刻、物件、空间、比分或名单
2. `contact`
   - 人对人 / 人对物 / 人对门槛发生实际作用
3. `shift`
   - 压力、位置、风险或结果发生偏转
4. `residue`
   - 留下余波，把下一段逼出来

如果一个段落同时缺少 `contact` 和 `shift`，它大概率仍然只是摘要。

## Dramatic Causality

关键场面默认补问五件事：

- 即时目标是什么
- 阻力是什么
- 主动动作是什么
- 偏转点是什么
- 代价或余波落在哪里

这五件事不需要逐条写成说明文，但读者读完以后应能大致复述出来。

## Tension Curve

同一章里，张力默认不应一直平着走。

- 允许出现：
  - 紧张
  - 短暂缓解
  - 更大的紧张
  - 结果落下后的余波
- 如果全章只是同一个音量持续播报，读感通常会发平
- dominant scene 前后的桥接、缓冲和回响，正是制造这种起伏的工具

## Change Ledger

每个场面、每一章，至少改变一项东西：

- `position`
  - 名单、身份、权限、归属、排位
- `risk`
  - 时间压力、失败代价、公开后果、物理风险
- `knowledge`
  - 谁知道了什么，谁还被蒙在鼓里
- `relation`
  - 信任、依赖、敌意、误解、债务
- `public consequence`
  - 名声、标签、纪录、舆论、制度性记录

如果段落很多，但 change ledger 几乎没有变化，读感通常会发平。

## Rhythm

- 开头尽量靠近 `disturbance`，不要先长时间热身
- 桥接可以压时间，但桥接不能吞掉整章最该落场的节点
- 安静、克制、留白是允许的，但必须携带压力
- 每章尽量至少有一个读者能复述的硬节点
- 章末优先留下 `residue`，而不是主题总结

## Compression Ladder

当一章里出现多个同型节点时，不要默认平均展开。

- 先问：这些节点是不是都在推动同一个 `change ledger`
- 如果答案接近“是”，优先做轻重分配：
  - 选 1 个最强节点写成硬场面
  - 选 1 个次强节点写成半展开段
  - 其余节点压成一句到两句桥接
  - 桥接如果承载多个节点，优先拆成多个极短段，一段只搬一件事
- 只有当不同节点分别改变了不同的 `position / risk / relation / public consequence`，才值得都展开
- 如果删掉其中一个节点后，章节压力线几乎不变，它大概率就不该占完整段落
- dominant scene 默认应明显慢于其它节点：允许它占掉全章最密、最具体、最能复述的连续空间
- 如果所谓“重点节点”和其它节点看起来一样快、一样粗、一样薄，说明轻重分配仍然失败

## Micro-Bridge Cuts

当桥接段仍然显得啰嗦、平均或像“简写版流水账”时，进一步收紧：

- 一段一件事
- 一件事只留一个最关键的可复述点
- 多个桥接段连续出现是允许的，它们的价值就在于快
- 这些段落应故意比主场面更短、更硬、更少解释
- 但不要把一个完整事件拆成多个词条式小段；桥接也应保留最小语义完整度

比赛线尤其要警惕：

- 不要把多个进球、多个赢球、多个关键传球都写成同一形状
- “重复证明自己”通常不是三个场面，而是一个场面加一组累计结果
- 读者要感觉到节奏在收、放、停、跳，而不是一直匀速向前

## Revision Lenses

返工时优先问：

1. 这一章能不能用三到五个事件节点复述出来
2. 哪个节点最值得被写成硬场面
3. 哪个人的压力反应最具体
4. 哪个转折改变了 ledger
5. 章末留下的是余波，还是作者结论
