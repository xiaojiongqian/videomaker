# Story Engine

把“更精彩”拆成少数可复用的内部检查，而不是更多空泛要求。

## Chapter Promise

在规划或扩写前，先在内部确认这一章的最小引擎：

1. `disturbance`
   - 什么在本章一开始就打破了原有平衡
2. `pursuit`
   - 这一章里，谁最急着想拿到什么
3. `escalation`
   - 什么让事情越来越难
4. `irreversible turn`
   - 哪个节点一旦发生，就不能再当没发生
5. `residue`
   - 章末留下了什么压力、债务、风险或未完成感

如果这五项里缺了两项以上，章节通常会滑向总结、综述或履历稿。

## Character Engine

关键人物不要只有“身份”和“功能”，至少要有最小可写引擎：

- `want`
  - 此刻想保住、拿到或阻止什么
- `risk`
  - 如果失败，会失去什么
- `pressure tell`
  - 压力落下时，动作、语言、节奏或回避方式如何变化
- `contradiction`
  - 这个人一边想要什么，一边又被什么拖住

对于纪实、历史、现实向写法：

- 如果来源不支持私密动机，不要硬写内心
- 把 `want / fear` 翻译成公开可见的等价物：
  - 即时目标
  - 外部代价
  - 位置矛盾
  - 可观察压力反应

## Scene Card

每个硬场面尽量能压成一张 scene card：

1. 进入时已有压力
2. 有人追求即时目标
3. 有阻力或反作用力
4. 有一次主动动作
5. 局面发生偏转
6. 留下代价、痕迹或未竟后果

如果一段只有“情况如何”而没有“谁做了什么把情况改变”，那通常还不是场面。

## Change Ledger

每个场面、每一章，至少改变一项东西：

- `position`
  - 名单、身份、权限、归属、排位
- `risk`
  - 时间压力、失败代价、公开后果、物理风险
- `knowledge`
  - 谁知道了什么，谁还被蒙在鼓里
- `relation`
  - 信任、依赖、敌意、误解、债务
- `public consequence`
  - 名声、标签、纪录、舆论、制度性记录

如果段落很多，但 change ledger 几乎没有变化，读感通常会发平。

## Rhythm

- 开头尽量靠近 `disturbance`，不要先长时间热身
- 桥接可以压时间，但桥接不能吞掉整章最该落场的节点
- 安静、克制、留白是允许的，但必须携带压力
- 每章尽量至少有一个读者能复述的硬节点
- 章末优先留下 `residue`，而不是主题总结

## Revision Lenses

返工时优先问：

1. 这一章能不能用三到五个事件节点复述出来
2. 哪个节点最值得被写成硬场面
3. 哪个人的压力反应最具体
4. 哪个转折改变了 ledger
5. 章末留下的是余波，还是作者结论
