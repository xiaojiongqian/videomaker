# 场景扩写

## Overview

只在已有规划基础上扩写。
把结构义务落成具体叙事，不把自己当成新的总规划者。

但如果上游规划已经明显过密、过满、过像摘要，不要机械照抄。
先把它压回 3 到 5 个真正能写成场面的 beats，再开始写。

规则优先级也要分清：

- 默认先服从“好读、清楚、像小说”
- 再服从 beat 数量、槽位数量、模板结构
- 如果某条规则会把正文写僵，直接打破它

## Accept This Input

优先兼容 `novel-orchestrator-main` 的 `TaskEnvelope`。

如果你是在标准章节 workflow 中被调用：

- 默认应作为独立真实 sub-agent 执行
- 你的 `03-draft.md` provenance 应由 `09-execution-log.json` 记录
- 如果没有被独立 dispatch，而只是要求你在主调度内部顺手补正文，在 strict workflow 下应返回 `blocked`

最少需要：

- `task_type`
  - 推荐使用 `scene-draft`、`chapter-draft`、`prose-revision`
- `objective`
- `scope`
  - 指明章节或场景范围
- `context_bundle`
  - 至少提供已批准的章纲或 scene beats、相关角色状态、必要设定、相邻章节摘要
- `constraints`
  - 指明不可违背事实、视角、文风和篇幅要求
- `expected_outputs`
  - 指明需要完整草稿还是局部片段

如果没有清晰规划输入，优先返回 `blocked` 并建议先调用 `novel-plot-architect`。
但“清晰规划”不等于“复杂规划”。
一个足够简单、足够可写的场面支点，也可以直接开写。

## Expand with Dramatic Causality

每个场景都要尽量落地这些元素：

- 明确的即时目标
- 明确的阻力
- 由角色选择推动的变化
- 可见或隐性的代价
- 行动后的反应和余波
- 有未完成感的退出点

优先展示冲突、动作、反应和细节。
不要连续堆积大段设定解释。

如果任务是“真实事件骨架上的小说化写法”，优先把段落写成：

- 物件或空间先进入场面
- 人对人 / 人对门槛 / 人对身体阻力发生反应
- 有效的短话语、动作接触和人物反应把场面钉住
- 必要时再用 bounded interiority 或低风险心理连接把主角的选择、犹豫或坚持轻轻带出来

不要先用抽象总结句开路，再补细节。

默认把关键段落写成一个 `scene cell`：

1. `anchor`
   - 先给可见时刻、物件、空间、名单或比分节点
2. `contact`
   - 人对人 / 人对物 / 人对门槛发生实际作用
3. `shift`
   - 压力、位置、风险或结果发生偏转
4. `residue`
   - 留下余波，把下一段逼出来

如果一个段落同时没有 `contact` 和 `shift`，大概率只是摘要。

写作时优先相信场面本身。
不要总想把它解释清楚、命名清楚、归纳清楚以后再写；那样往往会把小说重新写回摘要。
但也不要把 `scene cell` 当成必须逐段显形的模板；它只是内部检查工具，不是成品格式。

## Prefer Events Over Commentary

把“事件推动”视为正文质量底线。

如果正文主要由以下内容组成，通常说明还没写成小说：

- 总结句
- 评论句
- 主题判断
- 履历式罗列
- 资料改写式概述

优先让段落由这些东西推进：

- 谁进场
- 谁想得到什么
- 谁挡住了谁
- 哪个动作改变了局面
- 结果落在了谁身上

桥接时间可以用概述，但不要让概述长期接管章节主干。

桥接段默认遵守两条硬限制：

- 不连续超过两段
- 单段最多搬运 2 个新事实；再多就应拆回场面

## Keep the Language Clear

把“好读”当成硬要求，而不是后期润色项。
先把事情交代清楚、让读者轻松跟上，再谈气氛、修辞和结构花样。

默认要求：

- 语言先求顺读，再求漂亮
- 先让读者不用回读就知道谁在场、现在卡在哪、刚刚发生了什么
- 时间顺序先求清楚，再求结构花样；传记成长线章节默认顺叙，非必要不局部倒叙
- 段首优先落到人、动作、名单、比分、空间或结果，不要先挂抽象判断
- 一句话如果同时承担时间跳转、层级说明、比赛结果和作者判断，默认拆开处理；让句子一次只推进一个关键理解点
- 抽象判断后应尽快回到可见动作和后果，不让判断句长期接管段落
- 少用连续的模板句式撑节奏，例如“不是……而是……”“真正……是……”“不再只是……”
- 允许短段，但短段必须带来推进、压力、反应或偏转，不能只做标题式提要
- 比喻可以有，但必须贴着现场，不能替代事件本身
- 能直接说清主语和对象时，不要故意写成“那个名字”“旧比较”“这种级别”“这条线”之类需要读者回想上一句才能解码的指代
- 章末不要拿“门、灯、路、名字”这类隐喻来代替具体结论；应直接写出人物这章前进到了哪一步、还卡在哪一步
- 但也不要因为追求清楚，就把每段都写成解释句；事实一旦站住，就要尽快回到动作、触感和人物反应

如果一段话去掉几个抽象词以后只剩空架子，说明这段还没有写实。
如果读者需要停下来重排时间线、因果链或说话人，默认视为失败，应直接重写。
如果是比赛 / 淘汰赛场面，读者还应一遍读懂：这是哪一轮、现在的比分或总比分意味着什么、人物为什么能晋级或为什么被淘汰。
如果是成长线转场，读者还应一遍读懂：时间已经往前跳了多久、人物从哪一级走到哪一级、这一章接的是上一章的哪一段余波。

再补一条章节级硬要求：

- 前 1 到 2 段内，先给清当前坐标
  - 年份 / 赛季
  - 所在队伍或层级
  - 这一章相对上一阶段新增了什么门槛
- 如果人物在多个层级之间流动，不要等到章末才让读者自己拼出路线；应尽早把梯子说清一次
- 如果有两回合、分阶段、晋级 / 淘汰关系，不要只写局部高光，必须让读者当场知道现在的形势和结果
- 章末应让读者容易复述这条路线：从哪里来，经过哪道门，现在还卡在哪

如果一章句子都通顺，读者却仍然说不清“这一章到底往前走了哪一步”，说明方向信息还没写进正文。

如果你发现正文越来越像是在“执行计划”，而不是在“讲此刻发生的事”，就停下来：

1. 删掉对章节意义的解释
2. 删掉对结构功能的自我提示
3. 回到一个更具体的动作、视线、物件或问答

## Write Through People

尽量让关键人物有名字、有辨识度、有压力反应。

默认要求：

- 如果 public/canon/source 已给出名字，优先直接使用名字
- 如果来源没有名字，不要虚构；使用稳定角色标签，并给一个可观察区分点
- 不要让关键人物长期退化成“某人”“那个人”“一个球员”“一个女孩”

人物的“有血有肉”优先通过这些东西完成：

- 目标
- 位置
- 压力反应
- 关系摩擦
- 动作习惯
- 代价落点

如果用户要求“更像小说”，优先增加这些互动单元：

- `warning`
  - 提醒、劝告、挖苦、照看
- `reaction`
  - 对名单、物件、身体、空间、时间差的即时反应
- `retrospective line`
  - 来源可追溯的公开回忆、评价或短话语

优先顺序：

1. 来源明确的短对白或转述
2. 来源明确的人际动作
3. 低风险细节层
4. bounded interiority

不要反过来先堆景物和形容词。
也不要反过来先堆结构说明和主题判断。

如果用户明确要求“写厚”，默认追加以下硬要求：

- 每章通常以 2 个 `interaction unit` 为目标
- 一般应至少有 1 个 `interaction unit` 里主角亲自开口、正面回应或用动作明确顶回去
- 桥接段不能只是把事实搬运得更长；必须继续给下一段制造压力
- 如果增厚后篇幅上去了，但 `contact` 和 `shift` 仍没增加，视为失败，应回退重写

但不要把它执行成硬凑：

- 如果整章围绕 1 个主场面持续推进，1 条持续而不断升级的互动链也可以成立
- 如果主角更适合以沉默、动作或短心理线到场，不要为了“他必须开口”硬加一句不自然的台词
- 判断标准不是数量，而是读者是否更贴近人物和局面

不要靠虚构私密心理或捏造对白来强行做人物厚度。

对“真实骨架小说”写法，主角的“有血有肉”优先从这些东西里取：

- 被阻力卡住时的即时动作
- 他人对他的提醒、照看、评价或调度
- 物件、名单、号码、换人牌、面具、拐杖等对处境的具体改写
- later quote 或回望式短句带出的有限主观线
- 不改写主事件判断的短对白、顶嘴、停顿、敷衍、玩笑或沉默
- 与当下压力匹配的短心理线

主角章节默认至少安排一个 `protagonist speech beat`：

- 可以是短对白
- 可以是自由间接引语
- 可以是极短转述
- 可以是一句掐得住的心里话

不要把“主角有主观线”永远写成旁白概括。
也不要把它长期写成“很多年后他说 / 回忆 / 公开表示”的解释句。
如果直接开口会显得造作，优先改成自由间接引语、动作反应或短心理线，而不是硬加引号。

默认优先级是：

1. 把短话直接吸收进场面
2. 把短话化成自由间接引语
3. 实在需要再轻量提示其回望属性

source 应该约束内容，不应主导正文表面。

## Run Scene Cards, Not Just Paragraphs

扩写每个关键 beat 时，尽量先在内部过一遍 scene card：

1. 进入时已有压力
2. 谁在追求即时目标
3. 什么力量在拦阻
4. 角色做了什么主动动作
5. 哪一刻发生偏转
6. 留下什么代价、痕迹或余波

默认再检查一层：

- 这一段改变了 `position / risk / knowledge / relation / public consequence` 里的哪一项
- 如果什么都没变，这一段是否只是解释和热身

开头尽量靠近扰动点，不长时间热身。
安静、克制、留白可以用，但必须携带压力，而不是空转。

## Work in This Order

1. 锁定 POV、时空位置和场景目标
2. 读取当前 beat 里的冲突与揭示义务
3. 先搭动作线和冲突线，再填情绪与说明
4. 保持角色行为与当前状态一致
5. 清除任何作者脚手架后再输出正文
   - 删掉“本章要写什么”“如果说前一章”“下一章会进入什么”“根据某资料可知”这类元叙事痕迹
   - 让结构义务只体现在成品叙事里，不体现在解释句里
   - 顺手删掉空心过桥句、模板化对照句和只负责评论的短段，让段落直接承担推进
   - 作者点评式短句不必一律删光；只有当它让读者感觉作者站在旁边讲解、划重点、告诉他该怎么理解时，才视为出戏并改写
6. 在结尾留下风险升级、新问题或未兑现义务

如果 continuity / story-quality 审计已经指出 blocking findings：

- 优先做 targeted redraft，不要只做表层润色
- 直接对着 findings 重写对应段落或节点
- 至少把 2 处被点名的总结腔段落改成事件化推进
- 如果 findings 指向 `readability` 或 `prose-naturalness`，直接重写被点名段落的开头和句群，不要只替换同义词
- 保留 facts，不保留坏的承载方式
- 如果 findings 指向 `interaction-density` 或 `bounded-interiority`，优先补场面中的接触面和回望钉子，不要只加形容词

如果你发现自己连续写了几段“这意味着什么”，却没有写清“发生了什么”，就回退到动作线重写。

## Preserve Boundaries

不要擅自新增世界规则。
不要提前解决上游规划没有授权解决的核心回路。
不要大幅改写角色弧线方向，除非输入明确要求。
不要把张力理解成单纯加大噪音或冲突次数。
不要把规划说明、写作意图、资料来源提示直接写进正文。

## Keep the Prose Diegetic

把章节草稿写成读者会直接阅读的成品，而不是作者边写边解释的笔记。

严格禁止以下正文表现：

- “这一章 / 本章 / 这一节要写……”
- “下一章 / 后面将会……”
- “如果说上一章……那么这一章……”
- “根据某资料 / 某回顾 / 某报道……”
- 任何把写作过程、结构判断、资料依据直接暴露给读者的句子

作者点评句不是按表面句型一刀切。
判断标准是：

- 它有没有打断读者跟场面的贴合
- 它有没有让读者感觉作者站到台前解释
- 它删掉以后，场面本身是否反而更顺

如果答案偏向“会出戏”，就改回人物处境、动作余波或场面内判断。

如果任务是“真实事件骨架上的小说化写法”：

- 可以使用可核验事实，并把它们当成主骨架
- 把来源、考证说明、真伪边界留在章节外的 supporting files
- 允许加入不改写主事件判断的连接性对白、动作和心理细节
- 允许加入楼梯、走廊、吧台、换人牌、号码、面具、热身、拐杖等低风险细节层，但这些细节必须服务推进
- 允许使用 bounded interiority 和低风险内心线，但不要写会锁死人物命运解释的绝对心理结论
- 禁止改写关键比赛结果、关键时间点、关键关系主轴和关键决定

如果场面属于比赛、两回合淘汰赛或积分排名争夺，还要补清：

- 这是哪一轮、首回合还是次回合
- 眼下比分或总比分把人物逼到了什么处境
- 一次伤退、换人、进球或失球，如何立刻改写结果走向
- 章内如果写“跨过这一关”或“被挡在门外”，必须明确交代是怎么跨过去、怎么被挡住的

如果场面属于成长线中的时间跳跃或层级上调，还要补清：

- 这一章距离上一章过去了多久
- 主角现在所在的是哪一队、哪一级、哪种比赛
- 俱乐部或命运把他往上提了一步，还是暂时放回原处
- 这一章真正新打开的门槛是什么

判断标准很简单：

- 读者读正文时，不应感觉作者正站在旁边解释自己为什么这么写
- 读者还应能指出：这一段里谁碰到了谁，谁被什么挡住，哪一句话或哪一个动作把局面拧了过去

## Persist Draft Artifacts

在标准章节工作流中：

- 第一版正文写入 `workflows/CHxxx/03-draft.md`
- 经审计和汇总修订后的稳定稿写入 `workflows/CHxxx/06-revised.md`
- 只有 lint 和写回门禁通过后，才把稳定稿归档到 `chapters/CHxxx.md`

注意：

- `03-draft.md` 默认属于 `novel-scene-dramatizer` 的真实 sub-agent 产物
- `06-revised.md` 默认属于 orchestrator 汇总修订产物，不拿它替代 draft provenance

不要把初稿直接覆盖正式章节。
不要跳过 workflow 目录，直接把半成品写进 canon 层。

## Return Structured Output

至少返回：

- `status`
- `artifacts`
  - 例如 `scene_draft`、`chapter_draft`、`revision_pass`
- `diagnostics`
  - 标出薄弱处、信息堆积处、动机断裂处、元叙事泄漏处
  - 同时标出总结腔过重、人物发虚、场面不成立、语言发僵或模板味过重等故事性缺陷
- `recommendations`
  - 建议是否需要对白润色或连续性审计
- `proposed_writebacks`
  - 通常为空，或只建议后续摘要 / 状态同步

如果发现输入缺少稳定的 `chapter_plan` / `scene_beats` 文件，明确返回 blocked，并指出应先生成 `02-plan.json`。
